# Long-context requirement for Cloud9 engines — 25 Oct 2026
The previously reported 8K/16K are ONLY certification stress-test fixtures and Cloud9 router is even set to 2048 tokens for the LAB Chimera profile. They are not model architecture limits nor an acceptable maximum for generic agentic tasks.
Read ACTUAL local GGUF header without loading weights: Qwen3.5 4B EmperoAI Qwen3.8 Distill; architecture qwen35, trained/declared context_length=262144, full_attention_interval=4 with block_count=33 (may include MTP aux layer), 4 KV heads, K/V dimensions 256 each, recurrent/SSM hybrid with state size128. This matches published Qwen3.5 support but is NOT a real 262K runtime performance proof.
Agentic quality requirement: 32K first operational target, 64K follow-up, 128K qualification objective and 256K stretch, with real exact 5-marker retrieval across three repetitions, full prompt ingested, zero unsafe tool choice, latency/prefill and RAM/GPU guardian measurements. Never infer runtime 128K from model metadata or theoretical KV budget. The 16K f16 pilot failed memory PSI2.11 after ~6400 tokens (not evidence of a model context limit); alternate 16K q8 test has not yet safely launched.
GGUF KV planning estimates of q8_0 K/V memory are 0.60GiB at 32K, 1.20GiB 64K, 2.39GiB 128K, 4.78GiB 256K, not including weights, SSM, graph scratch, VRAM/UMA pageouts, system and agent workloads. Use supported native KV types, retrieval and summarisation; do not fill 128K for every agent request or permanently allocate large contexts when short requests suffice.
Official Qwen3.5 model card recommends at least 128K for complex tasks: https://huggingface.co/Qwen/Qwen3.5-4B . llama.cpp native K/V cache types: https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md . These sources do not establish speed on Radeon 780M.
