## New technologies considered and exact impact

1. **llama.cpp v0.6.0** (5 Oct, [upstream release](https://github.com/ggml-org/llama.cpp/releases/tag/v0.6.0)): ggml v0.26, sparse flash attention for quantized K/V on Vulkan, new mixed token/embedding `llama_batch_ext` API for MTP and deepstack, Qwen4Exp MTP support, typed audio/image/video `/v1/embeddings`. Investigate accuracy and memory on our **existing** small/MoE winners. Do **not** assume new typed multimedia embeddings can replace the existing Qwen3-Embedding-0.6B 1024-dimensional index or act as speech ASR.
2. **llama.cpp b11583** (13 Oct 09:34Z): [`9880157`](https://github.com/ggml-org/llama.cpp/commit/98801578818b26d833a1fe244870d64b0c34bb46) avoids graph reallocations on `no-cache` path. This is relevant to the production-style `cache_prompt=false` benchmark, but a new graph implementation can change allocation pressure on UMA. First A/B graph correctness with 4B and MoE, plus context 4K/16K, no-cache and warm-cache separated.
3. **llama.cpp master after b11583**: [`411d548`](https://github.com/ggml-org/llama.cpp/commit/411d548515017ca75c2a12c39659b6e7e1551dd7) (13 Oct 11:03Z) splits Vulkan matmul dispatch exceeding `maxComputeWorkGroupCount`; [`7f51953`](https://github.com/ggml-org/llama.cpp/commit/7f51953d7d) allows image embeddings for Qwen3.8 Flash-Next MTP; [`296538a`](https://github.com/ggml-org/llama.cpp/commit/296538adea) changes speculative graph assert. These are **post-b11583 HEAD** candidate changes, not in the b11583 tagged binary. Differentiate tags from master.
4. **Vulkan f16 FMA** [`0f701c8`](https://github.com/ggml-org/llama.cpp/commit/0f701c88298606b41a13268a027e97c877ff63ca) (12 Oct): packed FMA for F16 accumulators without dot-product op; interesting on Radeon 780M, but verify whether the gfx1103 shader paths actually use it and compare equal-model outputs within tolerances. Vulkan GQA flash attention grouping proposal [#29965](https://github.com/ggml-org/llama.cpp/issues/29965) is an open proposal on a Radeon 780M, **not an available certified feature**.
5. **Atomic TurboQuant 2.0** adds MoE expert cache (`--moe-cache`) across Vulkan/HIP/other backends, KV streaming arenas, TurboQuant quantized K/V Vulkan flash attention, newer AMD quant kernels and architectures Qwen4Exp/Muse Glimmer. Stage CPU-only source/flag support checks first; full GPU A/B strictly after 780M recovery, monitor peak RAM/GTT, expert cache residency, accuracy on repeated real agents and podcast inputs. Do not force Atom 2.0 over the stable upstream fork.
6. **Prism latest**: keep Ternary/Bonsai PTQ1 gate, compare identical model with old/new Prism commit and ensure the same schema and actual task outputs. Changes in generic upstream do not automatically translate to Ternary performance.
7. **Strata 0.1.43.1**: the 0.1.43 adaptive overlap was regressive on some GPUs, and the 0.1.43.1 hotfix returned overlap to opt-in; for Cloud9, default `STRATA_ADAPT_OVERLAP=0`. Its `STRATA_DEVICE_BUDGET_MIB=8192` is a **planning cap** and not proof of UMA VRAM availability. The machine's Strata best-safe historical Coder IQ1_M `5.96 tok/s` is an **experimental** result. Not comparable to llama.cpp Flash-Next AD4.27 FR-Spec 17.878 tok/s. Same-quant full-model HIP A/B required. **Strata is not a Qwen3-Embedding backend here**.
8. **ASR and word timing**: transcribe.cpp 0.4.0 can improve Nemotron throughput but GGUF Qwen word boundaries may remain unavailable; valid timings still require independent audio alignment. Do not silently run the built-in AutoSubs WhisperX aligner **twice**.

## GPU host blocker and promotion matrix

As of 13 Oct afternoon, Cloud9 Proxmox two kernel D-state processes from old testing are still present (PID 2625774 `llama-server/drm_suballoc_new`, PID 2683546 `cat/ttm_bo_evict_first`) and AMDGPU GTT ~10.64 GiB. The Radeon 780M shares the APU PCI bus with important controllers; PCI bus reset may disrupt the Proxmox host. Previous official GPU recovery attempt was blocked by RDC safety. **Do not bypass the security block, reboot host, reset PCI bus or queue new Vulkan/HIP inference while host GPU preflight exits REFUSE/4.** Four existing APIs were healthy at last check.

Once host GPU health is restored and any planned maintenance is authorized, validate in **DEV CT700**, benchmark identical model weights+GGUF SHA256, context/FA/KV, data and prompts against best historical Hall of Fame per engine; use 3+ runs, cold/warm, prefills, per-token decodes, latency p50/p95, RAM/GTT/swap, schema/tool call and content quality. Run AutoPublisher V22.3 **LLM only**, editorial extraction plus copy/visual prompts using actual transcript and `04-workflow` prompts; then one privacy-preserving read-only Archie contact lookup to validate the agent's tool use. **No real n8n, mail or publication test was performed today**, and historical two-tool agent simulation must not be mislabeled a real agent integration.
