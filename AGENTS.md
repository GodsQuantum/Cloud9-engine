# Cloud9 Engine — mandatory instructions for AI and human contributors

## The goal: latest-source native chimera for Radeon 780M / gfx1103

**Use only the latest available verified release or current upstream branch HEAD for any NEW benchmark, patch-porting baseline, selection, or production proposal.** The product's long-term goal is a *single maintainable native hybrid inference engine* incorporating the best currently available prefill, decode, speculative MTP, MoE expert-pooling, cache KV, and Flash-Next implementations tuned to AMD Ryzen 8845HS / RDNA3 UMA, together with correct tools/JSON/code/French, real useful context and safe 1/2/4-agent scheduling. Build and benchmark individual feature ports against the latest upstream, not historical forks. An unchanged upstream wins if the proposed chimera has no measured advantage.

- Read the local canonical project `POLITIQUE_LATEST_ET_CHIMERE_CLOUD9.md`, `GOAL_GENERAL_MOTEURS_IA.md`, `PLAN_EXECUTION_CONTINUE_MOTEURS_IA.md`, `PROTOCOLE_CANONIQUE_TOURNOI_ET_CHIMERES.md`, and current handoff before changing Cloud9 resources. The private docs live outside this Git repository on the authorized development volume; do not publish credentials or private machine configuration.
- **Fail-closed source freshness**: before *every* new build/benchmark/promotion verify upstream latest branches/releases and exact SHAs; use `python3 tools/benchmarks/verify_latest_sources.py --all` and the pinned `latest_engine_sources_20261023.json`. If a new release or HEAD appears, STOP/repin/rebuild/requalify. A missing API response is `UNVERIFIED`, not permission to skip the gate.
- **Fail-closed binary identity**: new GPU candidates require a known pinned ELF SHA-256, same SHA-model GGUF, explicit backend, matched KV/template/context/seeds. Lab candidate `rdna-r115-hip-4b` remains blocked while its new cross-build is unqualified. Historical b11798/r111/r112 metrics remain valuable *only* for regression diagnosis and audit, not final Pareto or new tournaments.
- **Native chimera means porting kernels/features into one compatible current codebase**, with licensing and per-patch A/B/CI. Routing separate old inference servers is NOT a native chimera. Features must prove benefit in TTFT, prefill, decode, MTP, quality, long useful context, RSS/GTT, thermals and robustness before promotion.
- Cloud9 real GPU experiments need the host's official coexistence admission, exclusive GPU lock, thermal/memory/PSI watchdog and scoped cleanup; NEVER weaken those protections or restart/delete production/PBS/VMs for benchmarks. Compile on free eligible CI runners when possible. GPU execution and production promotion require user-authorized deployment gates.
- Source-of-truth results: immutable benchmark JSON, provenance/sha logs and the project's single Hall of Fame with historical/current separation. Do not state that an engine, especially Qwen Flash-Next >20 token/s, is certified without real on-device evidence for that exact model.

**Release discipline:** experimental lab branch and review PR first; never force-push, merge, overwrite production, install ROCm globally, change mounts, or reboot to facilitate a test. Maintain a rollback and time-stamped checkpoint before and after each durable action. Previous branch histories are historical, not an instruction to continue benchmarking outdated engines.
